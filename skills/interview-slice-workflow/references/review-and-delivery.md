# 实际验收与交付

## 自动和人工的边界

自动：路径/媒体存在、分段时间映射、合法速度、整帧边界、连续双语字幕、字体SHA/字形/宽度、辅助素材时长与不足一秒回人物候选、3帧封面、总帧数/尺寸/声轨/完整解码、最终哈希。

人工：原话和译文准确、人物居中/脸部不遮、主题提炼承接、字幕阅读时长、真实素材语义和身份、源内部快切是否可读、背景深度/封面吸引力/手机版式、音乐情绪与人声听感。自动矩形碰撞提示不是人脸识别；没有问题提示不证明视觉合格。

## 证据格式

reports/review.json用evidence数组；每项写category、artifact、frame或timeRange、finding、status(reviewed/needs-change/not-reviewed)、reviewer。报告头绑定finalSha256。至少覆盖opening/crop/semantic/captions/broll/cover/audio；启用pip/alpha/danmaku时增加相应项。

不运行独立审片代理时如实由当前操作者审查；不能编造第二审阅者。合成演示无真实人物、不含自然语言原声，不能据此写真实访谈口型、语义或音乐听感通过。用户要求先看关键帧时交付真正可见预览，不做“我已看过”的空声明。

## 编码检查

运行prepare/validate后用render.mjs完整导出。verify读实际MP4/PNG，报告实际帧数和全帧解码；比较前三帧封面与第4帧正文。检查边界前/中/后帧，必要加source切镜。对音乐变更做实际声轨比较或试听，不能只读episode.json。

完成后正式标题命名（完整编号和分隔符），按有效分支交付：

```markdown
![01｜完整原标题](/absolute/path/01｜完整原标题.mp4)
[打开交付文件夹](</absolute/path/deliverables>)
```

当前运行环境支持时渲染播放器；文件夹链接用实际绝对目录。外盘缺失或路径不可读时先修入口。网页作为备用可cache-bust但不能主要交付网址。用户没要求新旁白、网页或额外视觉不要扩张范围。

给用户简述这轮结果、关键调整、实际验证与仍有的实质限制。来源核验/详细QA保存在工程，可点击查看，不用在视频里塞内部提示。
